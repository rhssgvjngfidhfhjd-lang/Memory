## 原版预期调用链及代码证据

```text
实验规定的一个 source observation（文字 + 原图）
→ AgentWrapper.send_message(memorizing=True, force_absorb_content=True)
→ TemporaryMessageAccumulator.add_message / absorb_content_into_memory
→ 原版 Meta Memory Agent
→ Meta Agent 的 trigger_memory_update 选择原版 Memory Agents
→ 原版 Memory Agent 工具循环
→ 原版 Managers 写入 SQLite 五类 memory
→ 原版 Managers embedding 检索（每分区最多 10 个候选）
→ Adapter 仅做 provenance 过滤、全局相似度排序和去重，最终 ≤7 条结构化 memory
→ 原版 Chat Agent system prompt + 原始 benchmark QA system/user messages
→ 原版 Chat Agent 工具循环（search_in_memory 等工具不冻结）
→ 原版 send_message 答案
```

可核对的原代码：

- `MMA/MMA/agent/agent_wrapper.py::AgentWrapper.send_message` 第 688–752 行：memorizing 输入进入 accumulator，`force_absorb_content` 立即触发吸收。
- `MMA/MMA/agent/temporary_message_accumulator.py::TemporaryMessageAccumulator.absorb_content_into_memory` 第 259–443 行：构造多模态 message，并在 `SKIP_META_MEMORY_MANAGER=False` 时发送给 Meta Memory Agent。
- 同文件 `_send_to_meta_memory_agent` / `_send_to_memory_agents_separately` 第 540 行起：由 Meta Agent 的原生工具结果选择并调用各 Memory Agent。
- `MMA/MMA/agent/agent.py::Agent.inner_step` 第 1365–1424 行：组装原版 system prompt、调用模型并执行原生工具循环。
- `MMA/MMA/agent/agent.py::Agent.build_system_prompt_with_memories` 第 1121–1215 行：通过原版 Managers 做 embedding 检索并构造 memory system prompt。

官方 commit 中不存在名为 CoPe 或 graph traversal 的 MMA 实现，因此没有根据论文或其他 baseline 臆造该阶段。这里复现的是上述 commit 实际存在的五类 Manager embedding 检索和 Chat Agent 工具检索。

## 实验输入与 Adapter 边界

- Mem-Gallery：`build_omni_memgallery_chunks`，每个 dialogue round 独立，正文包含 user、assistant、image_caption，原图在 `Chunk.images`。
- H2HMEM：`build_omni_h2h_chunks_from_directory`，每个 source turn 独立。
- WorldMemArena：`build_omni_wma_chunks_from_data`，每个 source turn 独立。
- 每个 chunk 都单独 `force_absorb_content=True`，不跨 round/turn 合并；session 结束不发送空消息。
- Adapter 只桥接 endpoint/model、隔离 SQLite 与图片目录、本地图像到 MMA `database_image_id`、memory-id provenance、最终 Top-7 和 benchmark 消息传输。
- 没有 semantic fallback、direct insert、文本工具调用解析/修补、空消息 flush 或冻结 Manager。
- 原版八个 Agent prompt 的 SHA256 固化在 run manifest；benchmark QA prompt hash 也写入同一 manifest。

## 方案 A：D2:6 + QA 2 对齐 diagnostic smoke

为防止再次发生错位，Mem-Gallery harness 新增了非计分的 `--integration-dialogue-ids` 入口，并在任何模型调用前验证所选 QA 的全部 annotated clue 是否已包含在建库 chunks 中。定向模式不能与 split manifest、`--all-datasets` 或 chunk prefix 混用；成功 manifest 会明确记录 `diagnostic_smoke=true`、`formal_evaluation=false`。旧组合 `integration_chunk_limit=1 + qa_indices=2` 的实测结果为零模型调用并立即报错：`QA 2: missing ['D2:6']`。

对齐执行使用 `D2:6 + D2:IMG_001` 建库并回答 QA 2，结果目录：

- 原生数据库：`Offline/outputs/Mem-Gallery/MMA/0913_mma_original_vllm_gpu4_d2_6_qa2_smoke/memory/datasets/Fashion_Personal_Care_Lifestyle_Shopping/sqlite.db`
- 调用 trace：`Offline/outputs/Mem-Gallery/MMA/0913_mma_original_vllm_gpu4_d2_6_qa2_smoke/call_traces/Fashion_Personal_Care_Lifestyle_Shopping-b765e7202fb0.jsonl`
- 31 次本地调用全部 HTTP/模型成功：`memory_build=4`、`qa=27`，累计 148208 tokens；全部调用 `image_count=1`。
- 原版 Managers 写入 1 条 episodic memory 和 1 条 semantic memory；episodic `occurred_at=2024-07-27 00:00:00`，原图位于 sample 隔离的 `images/`。
- Chat Agent 在正确 evidence 下直接生成了正确答案 `D2:IMG_001`，证明 dialogue/image 传输、建库、检索和视觉判断已经对齐。
- 最终仍未通过严格输出契约：模型把 `D2:IMG_001` 作为普通正文或无标签的 `send_message` 发送，没有原生生成 `<answer>D2:IMG_001</answer>`；三次完整尝试后严格失败，未伪造结果或通过 manifest。

对齐过程中还修复了 pinned 官方 commit 内部的两个传输兼容问题，但没有修改官方 checkout 或 Manager 算法：

1. `prepare_embeddings_from_config` 在同一官方 tree 中同时存在 tuple 与 episodic keyword/dict 两套调用契约，Adapter 现在按调用形式桥接返回结构。
2. 所有已提前 import `embedding_model` 的官方模块现在都使用配置的 `Qwen/Qwen3-VL-Embedding-2B`，不再从遗漏引用退回 `text-embedding-ada-002`；仅日期时间戳无损表示为当天 `00:00:00`，满足原版 episodic schema。

相关回归测试共 170 项通过；官方 checkout 仍为干净的固定 commit/tree。

## 当前验收结论与阻塞

结论：方案 A 已排除旧 smoke 的数据错位，并验证正确 evidence 下的建库、原图传输、Meta/Memory Agent、Manager 写库、Top-7 handoff 和视觉答案语义；本地 vLLM 的完整 E2E 仍因最终输出标签 **尚未通过**。

剩余阻塞只发生在最终输出协议：先前 OpenRouter 8B 模型和本次本地 vLLM 4B 模型都未稳定同时遵循原版 Chat Agent 的 mandatory `send_message` 与 benchmark `<answer>` 协议。本地模型已经得到正确答案 `D2:IMG_001`，但三个完整 Chat Agent 尝试都没有产生带合法标签的原生最终答案。严格 Adapter 没有把普通正文提升成工具调用，也没有补标签，最终报错：

```text
MMA Chat Agent failed the benchmark response contract after 3 attempt(s):
MMA Chat Agent violated the benchmark answer-tag contract; response rewriting is forbidden
```

因此该失败运行没有伪造 `results.json`、`retrieval_trace.jsonl` 或通过报告。当前继续保持严格模式：只有换用能原生遵守最终协议的本地模型，才可能完成 E2E 验收；不采用 Adapter 包装答案这一非原版路径。官方 checkout 未修改，执行后仍保持固定 commit/tree。
